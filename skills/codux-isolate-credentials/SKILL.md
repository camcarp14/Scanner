## Goal
Let an AI agent connect to SSH hosts and databases through Codux without any credential ever entering the model's prompt, context, transcript, or shell history.

## Steps

1. **Save SSH profiles in Codux's credential store**: host, port, auth method (key/password). Do this once, outside the AI CLI session.
2. **Save database profiles** (MySQL/PostgreSQL/SQLite) in Codux. Mark profiles read-only where the agent should not be able to write — Codux enforces a single-statement allowlist on read-only profiles inside the wrapper, so the model can't escalate its own access.
3. **Do not configure the AI CLI with inline credentials.** No per-project setup is needed for this step: every supported CLI learns about `codux-ssh` and `codux-db` automatically through Codux's environment directives.
4. **Let the agent discover profiles safely**: it should run `codux-ssh list` to see profile names and hosts only (never secrets), then connect with `codux-ssh <profile>`. For databases, it queries via `codux-db <profile>` by profile name.
5. **Credential injection happens out-of-band**: when the agent invokes `codux-ssh <profile>` or `codux-db <profile>`, passwords/keys are injected inside Codux's helper process — they never enter the model's context, transcript, or your shell history.
6. **Verify isolation**: inspect the AI CLI's transcript/context and your shell history after a session — no password, private key, or connection string should appear anywhere. Only profile names and hosts should be visible.

## Prerequisites
- Codux installed and running
- A supported AI CLI (Codex, Claude Code, OpenCode, or similar)
- SSH profile or database connection info already available to enter into Codux's store

## Notes / gotchas
- Don't paste passwords into prompts or let the model read raw SSH config/db connection files — that's the exact leak path this workflow avoids.
- Read-only DB enforcement is inside the wrapper (single-statement allowlist), not just a convention the model is trusted to follow.
- This is zero-config per project — if the agent isn't finding `codux-ssh`/`codux-db`, confirm you're running inside Codux's terminal wrapper, not a raw external shell.
