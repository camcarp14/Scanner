## Purpose
Install Agentsmith, a universal operating harness that assembles a lean `CLAUDE.md` (universal core + work-type profile) so an agent can run plan → implement → verify → ship loops with real autonomy, pausing only for things that genuinely need a human.

## Steps

1. **Run the wizard.** From the project root: `./setup.sh` (no flags = interactive wizard). It detects project type, asks scope (this project / global), and shows the exact command it will run before executing it. If working through an agent instead of a terminal, point it at `AGENT-INSTALL.md` and let it clone the harness and run setup itself.

2. **Pick the work-type profile(s).** Choose the profile matching the work: `software-dev`, `devops-setup`, `document-creation`, `marketing-outreach`, `data-crunching`, `research`, `design`, or `admin`. Profiles can be stacked. See `docs/07-how-to-pick-a-profile.md` if unsure. Reference the `examples/` folder for a filled-in project matching your profile — copy the *shape* of its `CLAUDE.md` and `.harness/verify.conf`, not literal commands.

3. **Let setup assemble CLAUDE.md.** setup.sh combines the universal core (rules that never change) with the chosen profile(s) into a deliberately lean `CLAUDE.md`. Install the core once globally, then add a thin profile per project.

4. **Define real verification gates.** Edit `.harness/verify.conf`: one phase per line, concrete commands (tests, build, lint, whatever makes it 'shippable' for this project), first failure stops the chain. This is the single most valuable file to get right early — `scripts/verify.sh` runs it to decide if work is done. Do not leave placeholder/generic commands; sharpen the profile's generic preset into your project's actual checks.

5. **Review the generated CLAUDE.md.** Confirm the universal rules plus profile-specific context read correctly for the project. Look for a `FIRST-STEPS.md` card left by setup — that's the onboarding doc for the first 30 minutes.

6. **Start the first session with one tracked item.** Give the agent a single unit of work; it runs plan → implement → verify → ship autonomously, deciding routing and scope itself, pausing only for missing credentials or genuine external surprises.

## Operating conventions to enforce afterward
- Bug fixes require a failing test first (prove-it) before the fix.
- Nothing ships without `verify.sh` passing — evidence before assertion, always.
- At ~25-30% context used (or on explicit "handoff"), the agent should safe-state and write a recall prompt so the next session resumes cleanly.
- When something breaks, fix the harness (sharpen a rule, add a gate), not just the immediate symptom — log it under `feedback/`.

## Gotchas
- `examples/` are reference artifacts only — not runnable; their verify.conf commands reference tools/paths that don't exist in the Agentsmith repo itself.
- Never put secrets, API keys, hostnames, or PII into CLAUDE.md, verify.conf, or examples (no-live-credentials rule).
- Docs under `docs/` are dynamic context — not loaded into the agent unless a task calls for them, so consult `docs/README.md`'s numbered reading order (01 philosophy, 02 first hour, 03 verify-means-evidence, etc.) rather than loading everything up front.
