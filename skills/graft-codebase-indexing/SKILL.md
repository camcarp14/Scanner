## Setup
1. `graft init` — detects installed coding agents (Claude Code, Cursor, Codex, Gemini) and wires them up; drops hooks/statusline into `.claude/` so Claude Code auto-pulls context each turn. Use `--dry-run` to preview, or `--agents claude` to skip the prompt. No global install needed: `npx @nanonets/graft init` works identically.
2. `graft build` — generates `graft/`, a folder of linked markdown nodes (one per system/API/concept), each explaining what a part does in plain English plus exact file:line spans and a who-calls-what wiring graph. `graft/` is auto-added to `.gitignore` — it's a regenerable local cache, not committed. Each teammate runs `graft build` themselves after pulling the `.claude/` wiring.

All query tools below refresh the graph before answering, so results reflect current uncommitted edits — no need to rebuild after editing. (Only the raw markdown cards under `graft/` can lag until end-of-turn; prefer the CLI tools over grepping those cards directly.)

## Query tools — use before grepping or opening files

**`graft ask "<question>" --source`** — default tool for "how does X work" / "where is X handled" questions. Ranked retrieval, routed automatically between prose nodes and the wiring graph. `--source` inlines the actual code (≤8-line crux) so the answer needs no follow-up file read; use `--full` only if the crux is too small. `--in <path>` narrows scope; `-n N` caps results (default 8). One `ask` per distinct sub-question — never reword the same question. Weak/few hits mean switch tools (grep/callers), not re-ask.

**`graft grep "<pattern>"`** — exhaustive search when you need *every* occurrence (all call sites, all uses of a constant): `ask` is ranked top-N and can miss instances. Supports `--fixed` for literal search, `-i` for case-insensitive, `--in` to scope. Search short symbol names/literals, not full guessed signatures — an over-specific regex returns nothing. If a search misses, loosen it and retry `graft grep`; do not fall back to raw `grep -rn` (slower, unranked) except for files graft doesn't index (docs, configs, brand-new files).

**`graft skeleton <file>`** — signatures-only view of one file's API in ~200 tokens, before editing or wiring into it. One call per file is enough.

**`graft callers <symbol>`** — precomputed call/reference edges (not text search). Symbol can be bare, qualified, or package-qualified.
- default `--direction in`: who calls/references this — run before renaming, deleting, or changing a signature.
- `--direction out`: what this symbol depends on.
- `--depth N`: transitive walk N hops (e.g. `--depth 2` for typical blast-radius).
- `--depth all`: full connected closure — use before any refactor, rename, or multi-file change to surface sibling/downstream files a single-file edit would miss.

**`graft map`** — token-budgeted architecture tour (directory clusters, hubs, hotspots) for orienting in an unfamiliar repo. Read the hub cards it names; don't then `ask`/`skeleton` through every listed subsystem. `--max-dirs N` widens it.

**`graft check`** — fails if `graft/` is stale; wire into CI.

## Task → tool mapping
- Onboarding / "explain this codebase": `graft map`, then read named hub cards.
- Understanding a flow: `graft ask "..." --source`.
- Finding where a change belongs: `graft ask "where is ..." --source`.
- Editing a symbol you already know the location of: `graft grep "<symbol>"`, skip `ask`.
- Renaming/deleting/changing a signature: `graft callers <symbol> --depth 2` first.
- Refactor / multi-file change: `graft callers <symbol> --depth all` before editing.
- "What does this depend on?": `graft callers <symbol> --direction out`.
- Finding every occurrence of a pattern: `graft grep "<pattern>"`.
- "What's the API of this file?": `graft skeleton <file>`.

All commands are free, need no API key, and return in under a second — prefer one targeted call and act on the result rather than chaining tools speculatively.
