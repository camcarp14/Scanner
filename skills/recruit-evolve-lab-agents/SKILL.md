## Prerequisites
- Janus desktop application installed (or self-hosted server for org-wide collaboration).
- Clear task scope and acceptance criteria defined before recruiting or assigning agents.
- Multiple agents recruited with assigned roles.

## Workflow

1. **Structure the task brief**
   - Turn the goal into a brief with: files/resources involved, constraints, and explicit acceptance criteria.
   - A vague goal should not be delegated until it has this structure — this is what uBuddy task intake expects.

2. **Delegate and sequence work**
   - Use One-to-N orchestration: assign the brief as direct work, to a specialist Agent, or across a dependency-aware multi-Agent workflow.
   - Sequence dependencies explicitly; consolidate outputs back into one deliverable.
   - Reserve human involvement for decision escalation (handoffs, recoverable issues, critical judgment calls) — not for routine coordination.

3. **Monitor performance and leadership**
   - Track each Agent's performance and leadership record as it executes tasks; these are distinct, auditable mechanisms from the Agent's Skill/Memory version.
   - Employee-lifecycle actions (recruit, assign, deactivate, reactivate, dismiss) are separate from performance/leadership actions (assess, promote, set leadership) — don't conflate them.

4. **Collect evidence for evolution**
   - Treat Agent capability as a governed, versioned process, not a fixed prompt.
   - Personal evolution: adapt an individual Agent's Skills/Memory using owner-specific work and feedback.
   - Cluster evolution: derive reusable, privacy-aware improvements from an eligible active Agent cohort's shared work evidence.
   - Only real work evidence should drive capability changes — do not evolve Skills/Memory speculatively without task evidence.

5. **Review before rollout**
   - Route cluster evolution outputs through the Talent Market: validate and publish versions before adoption.
   - Support controlled adoption or rollback — do not treat evolution as a single automatic chain from evidence to production; each stage (recruitment, evaluation, capability change, adoption) needs its own gate.

## Notes for repository work on Janus itself
- If a task touches schema, migrations, Sync contracts, identity/Workspace mapping, recovery, or quarantine, use `.agents/skills/safe-database-evolution/SKILL.md` instead of improvising.
- Relevant source areas: `src/main/` (Codex integration, persistence, scheduling), `assets/systemagents/` and `assets/departments/` (bundled agent definitions, skills, memories), `cloud/`/`network/` (org-wide evolution server pieces).
- Validate changes with `node scripts/runguarded.mjs -- node scripts/check.mjs`; add `fakecodexe2e.mjs` when touching Codex execution, routing, prompts, sessions, goals, projects, or persistence.
- For self-hosted org-wide evolution, the Evolution Worker must run as a separate service with its own credentials and should be tested in staging before enabling for users — never enable it for users without that staging pass.
